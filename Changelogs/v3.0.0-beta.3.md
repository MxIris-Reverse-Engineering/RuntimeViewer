# v3.0.0-beta.3

A repair release. Every privileged-helper feature in `v3.0.0-beta.2` was dead on
arrival, and the app gave no sign of it — the Settings pane reported the helper
as installed and enabled the whole time.

This is a `beta` build — only clients that opted in via
**Settings → Updates → Include pre-release versions** receive it.

---

## The privileged helper could not start at all

In `v3.0.0-beta.2` the helper daemon crashed the instant launchd started it, on
every attempt, from the moment the app was installed. Anything that goes through
the helper — attaching to another process, injecting, the file operations that
need elevated access — simply never worked.

Nothing said so. `SMAppService` reports whether the daemon is *registered*, not
whether it *runs*, so **Settings → Helper** stayed green. Meanwhile launchd kept
relaunching the daemon and it kept dying; one affected machine logged 1616
crashes in a day.

The daemon was dying in dyld, before a single line of its own code ran:

```
Library missing: @rpath/OSToolbox.framework/Versions/A/OSToolbox
```

The cause was a dependency that moved underneath the build. `FrameworkToolbox`
0.10.0 split `OSToolbox` into its own target and made a dynamically-built
target depend on it, which is enough for Xcode to build both as shared
frameworks. Everything then links them through `@rpath` — including the daemon,
whose only search path is `/usr/lib/swift`. The frameworks are embedded in the
app's `Contents/Frameworks`, the daemon lives in
`Contents/Library/LaunchServices`, and it has no way to look there.

`v3.0.0-beta.1` was unaffected: it predates that release of the dependency, and
its daemon links no such framework at all.

The version was never requested. The dependency was declared as "0.9.0 or
newer", which still admits 0.10.0, and the release archive re-resolved onto it.
It is now pinned exactly, and the built daemon once again links nothing through
`@rpath`.

## Settings changed right before quitting could be lost

Settings are written a second after the last edit, and each new edit restarts
that timer. Changing something and immediately pressing ⌘Q therefore quit before
the write, and the change was gone on the next launch. This affected every
build, not just the betas.

Quitting now finishes the write first.
