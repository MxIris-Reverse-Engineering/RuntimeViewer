# v3.0.0-beta.2

A follow-up to the first 3.0 preview, fixing two problems that only showed up
once people were actually using it: simulator injection did not work in the
released build at all, and the Xcode-backed content view could take the app down
on an ordinary sidebar click.

This is a `beta` build — only clients that opted in via
**Settings → Updates → Include pre-release versions** receive it.

---

## Simulator injection worked in Debug and not in the release build

`v3.0.0-beta.1` shipped iOS Simulator injection, and it failed for everyone who
installed it. The daemon reported:

```
dlopen payload: ... (fat file, but missing compatible architecture
(have 'x86_64,arm64', need 'arm64e'))
```

That `dlopen` runs inside the daemon rather than the target, so the architecture
it insists on is the daemon's own — and a release daemon is arm64e. A simulator
payload has no arm64e slice and cannot have one, so the demand could never be
met.

Reaching that code path was the real bug. The helper chose its injection
strategy from the target's sandbox alone, and every simulator process is
sandboxed, so it went straight to the remap fallback without first trying the
plain `dlopen` that would have worked. It now reads the target's platform too
and refuses the remap fallback for a cross-platform target. Debug builds hid
this the whole time, because a Debug daemon is not arm64e.

The payload is also embedded differently now — the same fixed-path arrangement
the Catalyst helper has always used, rather than a build-time script that had to
guess where the product landed under `xcodebuild archive`.

## The Xcode content view crashed when switching class after folding

With **Settings → Editor → Use Xcode Source Editor** on, folding a block and
then clicking a different class in the sidebar terminated the app. Not a glitch
— the process died, taking the window's state with it.

Folds belong to the editor view, not to the text: replacing the displayed source
left the previous interface's folds in place, and the first layout pass that met
a shorter line than the fold's recorded end column tripped a bounds check inside
Xcode's framework. Because that layout runs inside the click's own event
tracking, the crash looked like the click itself.

Nothing about it was version-specific — the same code is byte-identical in
Xcode 26.5 and 26.6, and still present in 27.0 — so no Xcode version avoided it.

**Folds now survive leaving an interface and coming back.** Clearing them before
each swap is what makes the crash impossible, so the fold state is saved first
and restored when the same interface returns, keyed on the rendered text: change
any generation option and the text changes with it, so stale folds are never
reapplied to something they no longer fit.

## The sidebar's case toggle now reads Match Case

The filter field's "Aa" button was labelled "Case Insensitive" and started
highlighted, which meant *clearing* the highlight made the search stricter — the
opposite of what that icon does in Xcode, VS Code and Safari, and the opposite of
every other button in that field, where a highlighted filter means "this option
is in effect".

It is now **Match Case**, unselected by default. The effective default is
unchanged: searches still ignore case until you ask otherwise.

## Smaller changes

- The attach sheet's application and process pickers are rendered as lists
  explicitly, rather than relying on the default style.
- `--update-packages` now really updates: it drops the resolved workspace state
  that was feeding the old versions straight back in.
