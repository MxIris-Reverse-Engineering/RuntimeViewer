# v3.0.0-beta.4

A smaller release than the last one. The sidebar gives back a large amount of
memory on big images, reinstalling the privileged helper is now one click instead
of two, and a transition artifact in the sidebar is gone.

This is a `beta` build — only clients that opted in via
**Settings → Updates → Include pre-release versions** receive it.

---

## The sidebar carries much less weight on large images

Every row in the sidebar exposes its display state — icons, names, filter
highlighting — as an individually observable property, and until now each of
those properties allocated its own observable relay and lock the moment the row
was created. On a 14,000-object image that cost was paid up front for every row,
including the overwhelming majority that are never scrolled to, and for
properties that nothing was ever watching.

Those properties now cost nothing until something actually observes them. The
storage lives inline in the row object, and the relay is built on first
subscription rather than on creation. Rows you never scroll to, and properties
nothing binds against, no longer allocate anything at all.

This is invisible except in how the app feels on large images: less memory held,
and less work done while building a list.

## Reinstalling the privileged helper takes one click

Replacing the helper daemon previously meant going to **Settings → Helper**,
clicking Uninstall, waiting for the status to settle, and then clicking Install
— and getting the order wrong left the helper unregistered.

There is now a **Reinstall** button next to Uninstall, shown whenever the helper
is installed and enabled. It performs both halves in the correct order, with the
delay the system needs between them, and reports the outcome in the status row.

This release also ships a new helper protocol version, so clients updating from
an earlier build will replace their installed helper automatically on first
launch.

## The sidebar's navigation transition holds an opaque background

On macOS 26 the sidebar's panes no longer carry a background of their own, which
left the transition between them translucent as one slid over the other. Both
panes now hold an opaque background for the duration of the transition and get
their original appearance back afterwards.
