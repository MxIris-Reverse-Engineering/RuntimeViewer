# Draft - 批量导出的镜像选择改成三态勾选树，搜索支持正则

- **状态**: In Progress
- **创建日期**: 2026-10-01
- **最后更新**: 2026-10-01

## 摘要

批量导出向导的第一步（选镜像）现在是一张平铺的表。侧边栏那棵镜像树被拍平了，每行只在右侧标一个分组名（`Dyld Shared Cache` 或 `Others`）。搜索只按镜像名做不区分大小写的「包含」匹配，Select All 也只作用于搜索结果。结果是「只选 Others 下的全部镜像」「只选 PrivateFrameworks」这类需求只能一行一行点，也没法用正则筛。

本提案把这一步换成一棵树（`NSOutlineView`），数据和侧边栏是同一份。每行有一个三态勾选框（全选 / 部分选中 / 未选），勾一个目录就选中它下面的镜像。搜索新增三项：正则模式、区分大小写开关、「匹配镜像名 / 匹配完整路径」切换。向导后面三步不动。

## 方案

**树**
- 数据取自 `documentState.runtimeEngine.imageNodes`，也就是侧边栏镜像列表的那两棵树（`Dyld Shared Cache` 和 `Others`）。
- 节点、排序都和侧边栏一致（同级按名字升序），只有一个子项的目录链也不合并。叶子是镜像，其余节点是路径上的目录。
- 打开时只展开两个根节点。

**搜索**
- 搜索框左边有两个弹出菜单：
  - 匹配方式：`Contains` / `Regular Expression`；
  - 匹配对象：`Name`（镜像名，如 `UIKitCore`）/ `Full Path`（如 `/System/Library/PrivateFrameworks/UIKitCore.framework/Versions/A/UIKitCore`）。
- 搜索框内有一个 Match Case 开关，样式同侧边栏对象列表。
- 只拿镜像（叶子）去匹配，目录名不参与。一个目录只在它下面有命中的镜像时才显示。
- 正则做的是不锚定的查找，和 grep 一样，要锚定就自己写 `^` / `$`。正则用 Swift `Regex`，在运行时由输入的字符串构造。
- 正则写错时树显示为空，摘要处给出错误原因，已有的勾选不受影响。
- 节奏和侧边栏一样：输入非空搜索词后停顿 150 ms 再计算，清空则立即生效。搜索期间树全部展开，清空后恢复原来的展开状态（用 `StatefulOutlineView` 的 `beginFiltering` / `endFiltering`）。

**勾选**

下文的「命中」指出现在当前过滤结果里的镜像，与是否展开无关；没有搜索词时，所有镜像都算命中。

- 唯一的事实来源仍是 `BatchExportingState.selectedImagePaths`，后面三步照旧只读它。
- 镜像行：点一下切换选中。
- 目录行：
  - 下面命中的镜像全部选中时显示 ☑，一个都没选时显示 ☐，其余情况显示部分选中（–）；
  - 点击时，如果是 ☑ 就取消它下面所有命中的镜像，否则把它们全部选中；
  - 因此「搜索 + 勾目录」等于取交集。例如用正则 `Kit$` 过滤后勾 `PrivateFrameworks`，只会选中名字以 Kit 结尾的私有框架。
- 目录行右侧显示「已选 / 命中」的数量。
- Select All / Deselect All 作用于全部命中的镜像（和今天一样）。
- 底部摘要保留「N of M selected」，搜索时再加上命中数。

**代码落点**
- 和 UI 无关的逻辑放进 `RuntimeViewerApplication`，配一套 swift-testing 测试。包括：匹配、目录是否显示、三态计算、勾选规则。
- ViewModel、ViewController 和 cell 留在 App target 的 `BatchExporting/` 里，只负责把上述结果绑到界面。
- `BatchExportingImage`、`availableImages`、`selectedImages` 保留，后续步骤要用。删掉 `searchString` 和平铺列表的 cell 代码。

**不做**
- 通配符和模糊匹配：正则已经覆盖了通配符的能力；模糊匹配会把不相干的镜像也选进来。
- 合并单子项目录链。
- 记住上次的搜索选项和勾选。
- 改动侧边栏自己的搜索。

**分支**：`feature/batch-export-image-tree`，从 `next` 切出，worktree 为 `.worktrees/RuntimeViewer-BatchExportImageTree`。做完后合进 `next` 测试。

**验证**：swift-testing 覆盖上面那部分逻辑。App 只做编译验证；界面没有自动化测试，需要实际操作确认。

## 决策日志

| 日期 | 决定 | 理由 |
|------|------|------|
| 2026-10-01 | Created as Draft | 用户原话：「现在批量导出Picker体验不好，dyld cache 以外的image都被收录在Other，没有办法只选择Other的全部镜像，而且不能指定搜索模式，例如正则表达式 / 还有就是得弄成树形OutlineView这样，可以选择某个节点下的所有内容」 |
| 2026-10-01 | 有搜索词时，勾目录只作用于命中的镜像，三态也只按命中的镜像计算 | 用户选定。搜索 + 勾目录取交集，正则筛出来的结果才能直接变成选择 |
| 2026-10-01 | 搜索可在镜像名和完整路径之间切换，目录名不参与匹配 | 用户选定。侧边栏的规则是「目录名命中就显示整棵子树」，放到选择场景会多选：搜 `lib` 会命中 `/usr/lib`，这时 Select All 就把里面所有 dylib 都选上了 |
| 2026-10-01 | 树的形状照搬侧边栏，不合并单子项目录链 | 用户选定。同一份数据、同样的排序，不引入新概念 |
| 2026-10-01 | 只提供「包含」和「正则」两种匹配方式 | 自行决定，理由见「不做」 |
| 2026-10-01 | Draft → Accepted → In Progress | 用户批准开工（「开Worktree实现」） |
| 2026-10-01 | 行本身不能被选中（`outlineView(_:shouldSelectItem:)` 恒为 `false`），只有勾选框起作用 | 原来的表格也是选中了看不见；放到树里，这种看不见的选中行会在清空搜索后被 `StatefulOutlineView` 恢复并滚动过去 |
| 2026-10-01 | 每次装上搜索结果后显式 `reloadData()` | RxAppKit 的 `rx.nodes` 只比较根节点数组，而搜索往往只改子节点，它会跳过刷新。侧边栏镜像列表也是这么处理的 |
| 2026-10-01 | 根节点永远当目录处理 | 旧的拍平代码会把没有子项的根（比如空的 `Others`）当成路径为 `/` 的镜像列出来；新树不会 |
| 2026-10-01 | 已知遗留：搜索前若两个根节点都已折叠，清空搜索后整棵树保持全展开 | `StatefulOutlineView.endFiltering()` 在既没有保存的展开项、也没有选中行时直接回到空闲状态，不做恢复，而本树的行从不被选中。侧边栏镜像列表用的是同一段逻辑（未在侧边栏里实测），修它会连带改变侧边栏，不在本提案范围内，待用户决定 |
| 2026-10-01 | 实现完成，待界面确认 | `BatchExportingImageTreeTests` 共 15 个测试（含 13 个参数化用例）全部通过，原始退出码为 0；临时去掉代次检查后，「旧查询被新查询取代」那个测试如预期失败，说明它确实测到了东西。App 以 Debug 配置完整构建成功，改动的文件没有警告。界面部分没有自动化测试，需要实际操作确认 |
