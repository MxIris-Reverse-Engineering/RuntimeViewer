摘要

iOS、越狱版 iOS 与 visionOS 的 RuntimeViewer 有了设置页：侧栏右上角一个齿轮按钮，点开弹出设置，列着外观（跟随系统 / 浅色 / 深色）、主题（字号、配色方案与自定义颜色）、转换选项（生成接口时的类型与偏移写法）三页。页面复用 Mac 版的 SwiftUI 代码，只把 Mac 专属的几处换成两边都能用的写法（转换选项页的模板编辑器另写一份 UIKit 版）；宿主是上游 UIFoundation 新增的 iOS 设置界面。顺带两处让设置在 iOS 上真正生效：内容区改为跟随设置里的主题（现在固定用默认主题），外观设置作用到 App 的所有窗口。Mac 版不变。

关联

  • 所属愿景：iOS 版功能对齐（第五步「iOS 前端逐项补齐」里的设置页，提前做）
  • 关联提案：0100-settings-storage-on-ios（iOS 上的设置已经存盘）；上游 UIFoundation 的 0043-settings-ui-on-ios（写页面的组件放开到 iOS，加 iOS 宿主，已随 0.49.0 发布）
  • 配套文档：待定 —— 预计无单独文档，规则写进 RuntimeViewerUsingUIKit/AGENTS.md
  • 网页版：同目录同名的 .html

动机

完整动机见愿景《iOS 版功能对齐》。这一步特有的：

  • iOS 上没有任何改设置的地方：0100 让设置能存盘了，但 iOS App 里没有入口，用户也就看不到任何变化；用户要先看到界面再验收这条线上的工作，所以把愿景第五步里的设置页提前。
  • 只放 iOS 上现在起作用的页：iOS 上会读设置的只有内容区的主题、生成接口的转换选项（ViewModel.currentMergedGenerationOptions，RuntimeViewerPackages/Sources/RuntimeViewerAppCore/Base/ViewModel.swift:55）；外观是用户点名要的，需要在 iOS 上新接。索引、搜索、文件、MCP、更新、helper 等页在 iOS 上没有对应功能，放进来只会让人困惑。
  • 主题在 iOS 上其实还没生效：ContentTextRenderer 在 macOS 之外默认用 ResolvedTheme.fallback（RuntimeViewerPackages/Sources/RuntimeViewerAppUI/Content/ContentTextRenderer.swift:41-56），因为 ResolvedThemeStream 只在 AppKit 上编（Theme/ResolvedThemeStream.swift:1）——当初 iOS 没有存下来的设置，跟随也没意义。0100 之后理由不在了。

架构图

设置页在两个平台上的宿主与共用页面

  • 新增
  • 修改
  • 不变

两个宿主各自列页面，指向中间共用的页面代码：Mac 的 General 页只把外观一节换成共用的 AppearanceSettingsSection，iOS 的外观页只放这一节；转换选项页的模板编辑器分平台，Mac 用原来的 NSTextView 版，iOS 新写 UITextView 版。iOS 宿主继承上游新增的 SettingsViewController。

iOS App：入口、外观与内容区

  • 新增
  • 修改

齿轮按钮经 SidebarCoordinatorDelegate 报给 MainCoordinator，后者以 sheet 弹出设置；AppDelegate 读完设置后启动 AppearanceController，跟随外观设置给每个窗口设样式；内容区的渲染器改为跟随设置里的主题，并按主题设背景。

提议方案

  1. 上游先落地：UIFoundation 按 0043 发 0.49.0；RuntimeViewer 下限抬到 from: "0.49.0"，RuntimeViewerSettingsUI 在所有平台依赖 UIFoundationSettingsUI，RuntimeViewerAppUI 在所有平台依赖 RuntimeViewerSettingsUI。
  2. 三页能在 iOS 上编（RuntimeViewerSettingsUI）：
    • AppSettings.swift 去掉平台条件。
    • 外观：AppearancePicker 与它的选项视图挪进新文件 AppearanceSettingsSection.swift（各平台），Mac 的 GeneralSettingsView 用它、其余三节不变且仍只在 macOS；iOS 用新的 AppearanceSettingsView（SettingsForm 里只放这一节）。
    • 主题：ThemeSettingsView 放开；ColorValue.from(_:) 在 macOS 上原样走 NSColor，在 UIKit 上走 UIColor(color) 转到 sRGB。
    • 转换选项：TransformerSettingsView 放开；模板编辑器分平台——AppKit 的原样留着，UIKit 上新写 UITextView 版（同样把 ${名字} 显示成胶囊、读回时还原、随内容长高）；复制按钮按平台用 NSPasteboard 或 UIPasteboard。
    • 新增 SettingsViewController.swift（iOS、visionOS）：继承上游 SettingsViewController，三页：外观、主题、转换选项。
  3. 内容区跟随主题：ResolvedThemeStream 去掉 AppKit 条件，ContentTextRenderer 在所有平台默认用它；iOS 的 ContentTextViewController 按主题设文字视图的背景色。
  4. 外观作用到窗口：iOS App 新增 AppearanceController（与 Mac 的同名、同样在 @Dependency 后面），跟随 settings.general.appearance 给每个窗口设 overrideUserInterfaceStyle；SceneDelegate 建窗口时先套一次当前设置。
  5. 入口：SidebarCoordinator 给侧栏根页的导航栏加齿轮按钮，按下经 SidebarCoordinatorDelegate 告诉 MainCoordinator；MainRoute 加 .settings，以 sheet 弹出 SettingsViewController。
  6. 文档：RuntimeViewerUsingUIKit/AGENTS.md 加「设置页与外观」一节；根 AGENTS.md 的 Settings Integration 那句「设置界面在别的平台由 App 自己做」改成 iOS 用上游的宿主，Dependency floors 补 0.49.0；愿景表与两份索引登记本篇。

非目标

  • 其余设置页（通用里的 Mac 专属三节、编辑器、通知、索引、搜索、文件、MCP、更新、helper、开发者）：等对应功能到 iOS 时再加。
  • iPad 的双栏设置：用上游的单栏导航栈，iPad 上以 sheet 弹出。
  • Mac 版任何变化：页面在 macOS 上的内容与行为不变，GeneralSettingsView 只是把外观一节挪进共用文件。
  • 把 iOS 的 MainRoute、MainViewModel 并进 AppCore：愿景第三步做；本篇照现在 iOS App 的结构加一个路由。
  • iOS 设置的单元测试替身与 UI 测试：iOS App 没有测试 target。

详细设计

iOS 的设置宿主子类 
// RuntimeViewerSettingsUI/SettingsViewController.swift
#if os(iOS) || os(visionOS)
import UIFoundationSettingsUI

package final class SettingsViewController: UIFoundationSettingsUI.SettingsViewController {
    package init() {
        super.init(title: "Settings") {
            SettingsPage("Appearance", id: "appearance", plainSymbol: "circle.lefthalf.filled") {
                AppearanceSettingsView()
            }
            SettingsPage("Theme", id: "theme", plainSymbol: "paintpalette") {
                ThemeSettingsView()
            }
            SettingsPage("Transformer", id: "transformer", plainSymbol: "arrow.triangle.2.circlepath") {
                TransformerSettingsView()
            }
        }
    }
}
#endif
iOS 的 AppearanceController 
// RuntimeViewerUsingUIKit/.../App/AppearanceController.swift
@MainActor
final class AppearanceController {
    fileprivate static let shared = AppearanceController()
    @Dependency(\.settings) private var settings
    private var observeToken: ObserveToken?

    func start()                         // observe settings.general.appearance → apply to every window
    func apply(to window: UIWindow)      // window.overrideUserInterfaceStyle = .unspecified / .light / .dark
}
取色、模板编辑器与主题流
  • 主题页的取色：iOS 上 UIColor(color) 先 cgColor.converted(to: CGColorSpace(name: CGColorSpace.sRGB)!, …)，转不了就返回 nil（与 macOS 一样，不覆盖原值）。macOS 分支一个字不改。
  • UIKit 模板编辑器：NSTextAttachment 的 image 用 UIGraphicsImageRenderer 画胶囊（与 AppKit 版同样的字体、内边距、强调色 15% 底色），附件子类记住名字；textViewDidChange 时把新出现的 ${名字} 换成附件、保持光标；读回时把附件换回 ${名字}；高度取 contentSize.height 回报给 SwiftUI。
  • 主题流在 iOS 上：ResolvedThemeStream 里只读 SettingsAccess（主线程）与 ResolvedTheme(settings:)，没有 AppKit 调用；订阅都在主线程，与 macOS 相同。

前期调研

现有的三页

RuntimeViewerPackages/Sources/RuntimeViewerSettingsUI/Components/，整份文件包在 #if os(macOS) 里：

  • GeneralSettingsView.swift（153 行）：外观一节用 AppearancePicker（三张缩略图，资源在本 target 的 Assets.xcassets），其余三节（工具栏样式、关最后一个窗口时退出、侧栏展开深度）只属于 Mac。
  • ThemeSettingsView.swift（436 行）：字号 Stepper、预设列表、颜色编辑（ColorPicker）都是 SwiftUI；唯一的 AppKit 用法是 ColorValue.from(_:) 用 NSColor(color).usingColorSpace(.sRGB) 取分量（:405-428）。
  • TransformerSettingsView.swift（1045 行）：各模块的编辑器是 SwiftUI；AppKit 部分是模板编辑器——TokenTextAttachmentCell 把 ${名字} 画成强调色胶囊、TokenTemplateTextView（NSTextView 子类）输入时把占位符换成胶囊、读回时还原（:277-529），以及 CopyableTokenChip 用 NSPasteboard 复制（:531-568）。FlowLayout（:1005）是 SwiftUI Layout。
上游

这些页写在 @AppSettings、SettingsForm 上，二者与 SettingsPage 只在 macOS 上有；上游提案 0043 把它们放开到 iOS、Catalyst、visionOS，并新增 SettingsViewController（UIKit 宿主），已随 0.49.0 发布。

依赖声明

RuntimeViewerSettingsUI 只在 AppKit 平台依赖 UIFoundationSettingsUI（RuntimeViewerPackages/Package.swift:424）；RuntimeViewerAppUI 只在 AppKit 平台依赖 RuntimeViewerSettingsUI（:486）。iOS App 链接的是门面 RuntimeViewerApplication（RuntimeViewerUsingUIKit.xcodeproj/project.xcproj:104-106），它再导出 AppUI。

iOS App 的结构

MainCoordinator（RuntimeViewerUsingUIKit/.../Main/MainCoordinator.swift）管一个双栏 UISplitViewController，MainRoute 在 App target 里；侧栏是 SidebarCoordinator 的导航控制器，根页 SidebarRootViewController；SidebarCoordinator 通过 SidebarCoordinatorDelegate 把完成的路由报给 MainCoordinator。iOS 的内容区 ContentTextViewController 用 ContentTextRenderer 的 renderedText，不设背景色（Mac 的内容区按主题设背景，RuntimeViewerUsingAppKit/.../Content/ContentTextViewController.swift:181-183）。

Mac 的外观

AppearanceController（RuntimeViewerUsingAppKit/.../App/AppearanceController.swift）用 SwiftNavigation.observe 跟随 settings.general.appearance，设 NSApp.appearance。iOS 上对应的是每个窗口的 overrideUserInterfaceStyle。

ResolvedTheme 本身跨平台

ThemeProfile.swift、ThemePreset+ThemeProfile.swift 只把 import 分平台，ResolvedTheme(settings:) 在 iOS 上就有，颜色是 NSUIColor，按 trait 自动取浅色或深色。

替代方案考量

4 个方案，均未采用
  • RuntimeViewer 自己写 iOS 版的三页、上游不动：用户选了复用，两套界面代码改一项要改两处。
  • iOS 上把模板编辑器换成普通文本框：胶囊是这页的主要价值，降级会让 iOS 版难用；UIKit 版不到两百行。
  • 入口放到系统「设置」App（Settings.bundle）：只能放简单的开关，放不下主题编辑与模板编辑器。
  • 外观只作用到当前窗口：设置是全局的，多窗口时会不一致。

影响

用户可见变化

  • iOS、越狱版 iOS 与 visionOS：侧栏右上角多一个齿轮按钮，点开是设置（外观、主题、转换选项三页）。
  • 内容区的字号、配色从此跟随设置里的主题，默认主题仍是 Xcode 预设、13 号字，所以没改过设置的人看到的与现在相同（背景色会按主题变——深色模式下背景跟着主题的深色背景）。
  • 外观设成浅色或深色后，App 不再跟随系统。
  • Mac 版：无变化。

可发现性

齿轮按钮是 iOS App 的惯例位置；三页的默认值都与现状一致，不改设置就没有变化。

数据与配置兼容

读写的是 0100 起已存盘的同一份 settings.json，不新增键。

平台与最低版本

最低版本不变（RuntimeViewerPackages：iOS 18、visionOS 2，高于上游要求的 17 / 1）。iOS 与越狱版行为相同；visionOS 同一套代码，外观在 visionOS 上的表现以系统为准。

发布

不需要新的权限或 entitlement；不影响公证与 Sparkle。UIFoundation 要先发 0.49.0。
