摘要

Generation Options 从工具栏的弹窗搬进设置窗口，成为 Settings › Generation Options 一页，那里改的是全局选项。每个 engine + 镜像可以逐项覆盖全局：覆盖的那几项用这个镜像自己的值，没覆盖的照旧跟着全局走，全局改了它们也跟着变。

覆盖在文档窗口里改：Editor › Generation Options for “<镜像名>”… 打开一个 sheet，列出这个镜像生效的选项，改一项就记成这一项的覆盖，改回与全局相同就自动去掉覆盖；被覆盖的行有标记和还原按钮。设置页列出所有覆盖，可以逐项还原或整条删除。工具栏的 Generation Options 按钮和弹窗删掉。

全局与覆盖都存在 settings.json 的新分支里，首次启动从旧的 UserDefaults 键 generationOptions 迁移一次。凡是按选项打印或投影 interface 的地方——内容区、复制与保存、单个与批量导出、命名词云、Find 的文本与成员搜索、交叉引用——都按对象所在镜像生效的选项来；CLI 的 --options app 与 MCP 只用全局。

要你定

已批准（2026-11-26）。两个设计问题已定：

  1. 覆盖粒度：逐项覆盖。
  2. 窗口入口：Editor 菜单打开 sheet，工具栏按钮删除。

agent 自定的假设（可推翻）

  • 存进 settings.json 并迁移旧 UserDefaults 键，旧键不删。
  • engine 键沿用 Always Index 的（附加的进程按进程名）；镜像路径用规范写法。
  • Find 每个镜像按各自的选项投影；搜索请求加一个可选字段，旧对端忽略即退回全局。
  • 内容区的 C 名标签只改当前镜像。
  • CLI 与 MCP 只用全局。
  • iOS 设置也加这一页（只有全局）。

改了什么

窗口的 sheet、设置页与内容区的 C 名标签都写同一个 Settings.generationOptions；所有消费者经 effectiveOptions 按对象所在镜像取选项，CLI 只读 global。

一次取 interface 与一次 Find 搜索

Find 的表只含这个 engine 有覆盖的镜像；没有表的请求与今天完全相同。内容区只在本镜像的生效选项变了时才重取。

提议方案

  1. 设置页：Settings › Generation Options（macOS 排在 Theme 与 Transformer 之间，符号 ellipsis.curlybraces），Objective-C、Swift 两组，控件与原弹窗一一对应。这里改全局。macOS 页末是 Image Overrides：每条覆盖一行（镜像名、engine 名、覆盖了几项），展开逐项列出并可还原，整条可删除。
  2. 存储：Settings 加顶层分支 generationOptions（global + imageOverrides）。首次启动迁移旧 UserDefaults 键，旧键不删。AppDefaults.options 删除。
  3. 逐项覆盖：engine 键 + 镜像规范路径认出一条覆盖，存「覆盖了哪几项」与值。生效 = 全局，覆盖的项换成覆盖值。改回与全局相同即去掉这一项，最后一项去掉时整条删掉。
  4. 窗口入口：Editor 菜单顶部 Generation Options for “<镜像名>”…，作用于聚焦编辑栏显示的镜像，空标签退到侧栏的镜像，都没有时灰掉。sheet：标题镜像名、副标题 engine 名；被覆盖的行加粗、带还原按钮；底部 Revert All、Global Options…、Done；改动即时生效。
  5. 按镜像解析：所有按选项打印或投影的地方都按对象所在镜像的生效选项；内容区、词云、Find 订阅生效选项。
  6. Find：请求多带一张「镜像路径 → 生效选项」的表（只含这个 engine 有覆盖的镜像），引擎按镜像投影；旧对端忽略即退回全局。
  7. C 名标签：只记成对象所在镜像的覆盖。
  8. 删掉工具栏按钮、MainRoute.generationOptions、generationOptionsClick，弹窗那一对改造成 sheet。
  9. CLI 与 MCP：--options app 读全局，不看覆盖；MCP 不变。
  10. iOS / visionOS：设置里加这一页，只有全局两组。

非目标

  • CLI、MCP 按镜像套用覆盖（留作后续项）。
  • 在设置页里新建或改覆盖的值：只看、还原、删除。
  • 按对象覆盖、按镜像名匹配、engine 之间共享覆盖。
  • 按镜像覆盖 Transformer 或编辑器显示设置。
  • 导出对话框里另选选项。
  • iOS 上设置覆盖的入口。

替代方案

8 条，均被否
  • 整套覆盖：覆盖后再改全局就影响不到它。用户选了逐项。
  • 保留工具栏按钮改成当前镜像：与「搬进设置」相反。用户选了菜单加 sheet。
  • 只在设置页管理覆盖：设置窗口没有「当前镜像」，新建覆盖要挑 engine 和镜像。
  • 覆盖存进 AppDefaults 文件存储：设置页要绑定与列出，放 Settings 里直接用 @AppSettings，CLI 也只读一处。
  • 为每种值造 enum 做稀疏字典：要写编解码与比较；完整 GenerationOptions 加一组选项名复用现成能力。
  • Find 只用全局：有覆盖的镜像里搜到的与内容区不一致，违背「逐字相同」。
  • 改回与全局相同时保留覆盖：会留下大量相同条目，看不出哪些真的不同；有需要再加「钉住」。
  • CLI 也按镜像套覆盖：独立 host 要自己算键与路径，留作后续项。

影响

用户可见变化

  • 工具栏不再有 Generation Options 按钮；全局在设置页，单个镜像在 Editor 菜单。
  • 设置多一页（iOS 也有，只有全局）。
  • C 名标签只改当前镜像；Find 在有覆盖的镜像里按那个镜像的选项搜。
  • 「只打印导出的声明」提示指向新位置。

可发现性

  • 设置侧栏可见新页；Editor 菜单项标题带镜像名；Image Overrides 为空时说明去哪设。What's New 是发版时的事。

数据与配置兼容

  • 首次启动迁移旧键，旧键不删；降级时旧版本读得到迁移前的值。迁移失败用默认值、旧数据留着。
  • 旧版本读新 settings.json 时忽略新键。新旧 CLI 与新旧 App 交叉组合都能读到全局。
  • Find 请求新字段可选，新旧对端交叉连接都按全局或今天的行为搜。

平台与最低版本

不变。iOS / visionOS 只有设置页的全局部分。

发布

无新权限、entitlement、隐私清单条目；不影响公证与 Sparkle。插件 skill 改了，两个清单的 version 升一级。
