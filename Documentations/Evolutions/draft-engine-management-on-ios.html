摘要

让 RuntimeViewerEngineManagement 在 iOS（含越狱版）与 visionOS 上编译并可用，Mac 上的行为一点不变。只属于 macOS 的三块——内嵌 XPC service、特权 helper daemon、Mac Catalyst——收进带 .live 的闭包接缝，iOS 上的 .live 是「没有这项能力」；配置新增「浏览局域网」与「服务端推送运行时数据」两个开关和一份 iOS 用的 .deviceApplication；iOS 上文件引擎直接在 App 进程里读。iOS app 把今天手工建的两个引擎（本机引擎、给 Mac 连的 Bonjour 服务端）交给管理器启动，Mac 看到的设备与今天一样。

不在这一篇：在设备上自己附加进程（另起一篇，和附加界面一起做）、iOS 上浏览局域网、共享系统镜像与派生数据、AppCore 链接管理器、任何界面变化。

要你定：批准这份提案（改为 Accepted）后开工。没有其他未决问题；实现由另一台 Mac 上的协作 agent 接手。

前期调研

管理器里只属于 macOS 的地方
位置（RuntimeEngineManager.swift）用到什么原因
:6import ServiceManagement没有用到，iOS SDK 也没有
:12-13HelperClient、CatalystExtensions只在 AppKit 平台链接
:98-100RuntimeFileService.credential(for:)文件 service 的 XPC 层只在 macOS
:209-218三个 helper 的 @Dependencykey 在 HelperClient
:282-343MacCatalystLaunching.liveCatalyst 与 helper daemon
:372共享缓存资格的探针探针在 HelperClient
:405、:421-428daemonAvailabilityPublisherhelper daemon
:1430-1465注入过的 Mac 进程的 XPC 重连daemon 注册表与 .xpcServer 凭据

其余约 85% 与平台无关：Bonjour 发现与心跳、镜像、共享、分区、.injectedTCP 设备引擎、socket 记录、文件引擎的簿记。

Bonjour 服务端一次只接一个客户端

RuntimeNetworkServerConnection 接受第一个连接后立刻停止监听，直到客户端断开（RuntimeNetworkServerConnection.swift:165-176、:240-275）。设备要是浏览，就会占掉 Mac 唯一的连接位。

管理器与 iOS app 的服务端有两处不同

名字：管理器用同步的 localServiceName，在 iPhone 上退回机型名；iOS app 用 resolvedServiceName()。旧版 Mac 拿这个名字当窗口标题与侧栏 autosave key。macOS 上两者相同。推送：管理器的服务端 pushesRuntimeData: false（Mac 的引擎经代理服务端镜像），iOS app 的服务端推送运行时数据（Mac 直接看设备）。另外 Mac 上 startSharingEngines() 紧跟着同步读服务端引擎（:1771-1780），所以 Mac 上必须同步创建。

文件在进程里读

RuntimeEngine(reading:engineID:hostInfo:) 同步建好文件目录，connect() 不带凭据即启动；读取代码没有平台限定。与 Mac 的 .file 引擎契约不同：Mac 上窗口先开、可挂起、可换配对、始终同一个对象。测试里在本进程供文件用的是 XPC 匿名监听，iOS 上没有。

现有接缝与 iOS 工程

接缝：MacCatalystLaunching、fileEngineCredential、sharedCacheEligibility、init 的 startupHandler。iOS 工程是 Xcode 27 的 project.xcproj，三个 target 编同一个源码目录，各自列链接的包产品，目前没有 RuntimeViewerEngineManagement；不在 Tuist 描述里。

替代方案考量

展开
  • 只用 #if 拆文件：iOS 的路径测试覆盖不到。选定的是接缝。
  • macOS 传输拆成独立模块：多一个模块，App 与命令行 host 的接线都要改。
  • 一个汇总的「平台服务」结构体：已有接缝是分开的，合并要改所有相关测试而不带来新行为。
  • iOS 上进程内也起一个「服务」保留 Mac 的转发契约：要在 Core 里新加进程内连接，超出本篇；留给 iOS 文件模式界面那篇。
  • iOS 上浏览，同时把服务端改成多客户端：本篇变大，改的是 Core 的连接层，而 iOS 上还没有切换来源的界面。
  • iOS 上也用同步的 localServiceName：设备名退回机型名，旧版 Mac 的窗口标题与侧栏状态跟着变。

影响

展开
  • 用户可见变化：无。Mac 一切照旧；iOS 界面不变，Mac 连设备、看运行时、注入都与今天相同。
  • 数据与配置兼容：设备广播的名字与身份不变，Mac 上按设备记的书签与侧栏状态照常对得上。
  • 平台：管理器从只在 macOS 上编变为 macOS、iOS、visionOS 都编；最低版本不变。Mac Catalyst 与 tvOS 上没有 target 链接它，不保证编过。
  • 发布：不需要新的权限或 entitlement；不影响公证与 Sparkle。
