摘要

macOS App 接入 swift-onboardingkit（Apple 私有框架 OnBoardingKit 的 Swift 封装，App Store、Freeform、Shortcuts 的欢迎页与 "What's New" 页就是它画的），做两种一次性页面：新用户第一次启动时的欢迎页，以及升级到新的功能版本（主版本.次版本）后第一次启动时的 What's New 页。

页面在文档窗口上是 sheet；0105 的欢迎窗口在前时（它是无边框窗口、不会成为主窗口），页面放在一个独立窗口里显示在它前面。点 Continue 关闭并记下「已看过这一版」；Help 菜单新增 What's New in RuntimeViewer，随时可再看。「这次启动该弹哪一页」由 RuntimeViewerAppCore 判断（可单测），页面内容是 AppCore 里的值，由 RuntimeViewerAppUI 画成 OnBoardingKit 的模板，App 里一个新的启动控制器负责弹出。

swift-onboardingkit 改为公开仓库、改成弱链接私有框架后发布 0.1.0，RV 按 from: "0.1.0" 依赖它，只给 macOS 链接。

要你定

实现已完成，等你目视验收

  1. 删掉 defaults 键 lastPresentedOnboardingRelease 与 settings.json 后启动：欢迎窗口前出现欢迎页。
  2. 保留 settings.json、只删 defaults 键后启动：出现 What's New in RuntimeViewer 3.0；点 Continue 后重启不再出现。
  3. Help › What’s New in RuntimeViewer 随时打开同一页。

没问你就采用的假设（可以推翻）

  • swift-onboardingkit 发版前改成弱链接：框架将来消失时 App 照常启动，只是不弹页面。
  • 新用户按「这次读设置时有没有找到 settings.json」认；从没改过设置的老用户会看到欢迎页而不是 What's New。
  • 按功能版本（3.0）弹 What's New，beta 与补丁版不重复弹。
  • 页面内容手写在 AppCore 里，取材于 3.0.0 各 beta 的 Changelogs；欢迎页 5 行、3.0 的 What's New 6 行。
  • 文档窗口上挂 sheet；欢迎窗口在前、或没有合适的文档窗口时，用独立窗口（实现中改的，原方案是也挂在欢迎窗口上）。
  • 目录缺当前版本时测试失败，强制下一个功能版本同批写 What's New。

#if os(macOS)

/// A feature release of the app: the major and minor parts of its marketing version.
public struct FeatureRelease: Hashable, Comparable, Codable, Sendable, CustomStringConvertible {
    public var major: Int
    public var minor: Int
    public init(major: Int, minor: Int)
    /// `3.0.0`, `3.0` and `3.0.1` are all 3.0. `nil` when the string does not start with two numbers.
    public init?(marketingVersion: String)
    public var description: String
}

public struct OnboardingPage: Equatable, Sendable {
    public enum Kind: Equatable, Sendable { case welcome; case whatsNew(FeatureRelease) }
    public struct Feature: Equatable, Sendable {
        public var title: String
        public var description: String
        public var symbol: SystemSymbol
        public init(_ title: String, description: String, symbol: SystemSymbol)
    }
    public var kind: Kind
    public var title: String
    public var bodyText: String?
    public var symbol: SystemSymbol
    public var features: [Feature]
}

public struct OnboardingCatalog: Sendable {
    public var welcomePage: OnboardingPage
    public var whatsNewPages: [FeatureRelease: OnboardingPage]
    public static let runtimeViewer: OnboardingCatalog
    /// The page Help › What's New shows: the release's own, or else the latest one before it.
    public func latestWhatsNewPage(upTo release: FeatureRelease) -> OnboardingPage?
}

public enum OnboardingPolicy {
    public static func pageForLaunch(
        currentRelease: FeatureRelease,
        lastPresentedRelease: FeatureRelease?,
        hasStoredSettings: Bool,
        catalog: OnboardingCatalog
    ) -> OnboardingPage?
}

Welcome to RuntimeViewer（hand.wave）

Read the Objective-C, Swift and C++ interfaces of the images on your Mac, in other processes and on your devices.

  • Every Interface — Browse the Objective-C, Swift and C++ objects of any image, printed with Xcode's syntax highlighting. — square.stack.3d.up
  • Jump Through Types — Click a type in an interface to open it, and go back the way you came. — arrow.right.circle
  • Beyond This Process — Attach to a running app, a Mac Catalyst app, the Simulator or a device, or open files from disk. — app.connected.to.app.below.fill
  • Find and Cross References — Search every indexed interface and follow callers, callees and type references. — magnifyingglass
  • Made for Agents — An MCP server and runtime-viewer-cli give coding agents the same interfaces. — terminal

What's New in RuntimeViewer 3.0（sparkles）

  • Find Navigator — Search the interfaces of every indexed image, find types with their hierarchy, and find members. — magnifyingglass
  • Cross References — See who calls a method, what it calls and which functions use a type. — arrow.triangle.branch
  • Files from Disk — Open Mach-O files, bundles, folders and dyld shared caches, each in its own window. — folder
  • C++ Interfaces — Classes and namespaces recovered from RTTI, vtables and symbols, printed and exported as headers. — curlybraces
  • Editor Panes — Split the content area; each pane has its own tabs, history and jump bar. — rectangle.split.2x1
  • Command-Line Tool — runtime-viewer-cli ships inside the app and works without it running. — terminal

调研

查证过的事实
  • swift-onboardingkit 只有一个提交，已推到 Mx-Iris/swift-onboardingkit 的 main，仓库私有、没有 tag；现在是强链接，框架不在时链接它的 App 启动即被 dyld 拒绝。
  • RuntimeViewer 是公开仓库；release workflow 只为 SourceEditor 配了额外的 token，其余依赖用 job 自己的 token，读不到别的私有仓库。
  • 带 unsafe flags 的远端依赖能否被 Xcode 与 Tuist 接受：尚未验证，本机没有工程依赖过同样写法的 swift-skylight。放在第 2 步实测。
  • SettingsAccess.load() 拿到的 LoadOutcome 现在只打日志；UIFoundation 设置层 skill 建议首次启动的判断从已持久化的状态推出。
  • AppDefaults 存 App 的非偏好状态；Debug 与 Release 的 bundle identifier 不同，defaults 天然分开。
  • MARKETING_VERSION = 3.0.0，所有 beta 都报 3.0.0，所以按 主版本.次版本 认功能版本。
  • Help 菜单是 UIFoundation 的 MainMenu.help()，另有接受 @MenuBuilder 的 help(title:_:)。
  • 升级后 HelperServiceVersionChecker 可能 runModal() 一个 alert；sheet 会等它结束才显示，不做特别处理。
  • Changelogs/*.md 的条目是整句话，没有标题与符号，内容只能手写。

替代方案

评估过但放弃的 8 条
  • 自己用 AppKit 画页面：外观永远差一点，系统改样式还得跟。
  • 保持私有、CI 加 token：公开仓库的贡献者解析不了依赖图；用户选了改公开。
  • 封装放进 UIFoundation 的 UIFoundationAppleInternal：用户已做成独立包，本提案只接入。
  • 另存 hasCompletedOnboarding 布尔值：同样认不出没改过设置的老用户，还多一份可能矛盾的状态。
  • 用 Sparkle 的 SUHasLaunchedBefore：内部键，且写入时机绑在 UpdaterService.start() 上，容易被启动顺序调整悄悄打破。
  • 按完整版本号或构建号弹：每个 beta 都弹一次，补丁版没东西可讲。
  • 一律用独立窗口：Apple 的 App 都挂在主窗口上；只在欢迎窗口在前或没有合适的文档窗口时用。
  • 挂成欢迎窗口的 sheet（最初的方案）：欢迎窗口无边框、不会成为主窗口，sheet 会从它没有标题栏的上沿垂下来，window 属性也被标成不可用。

影响

  • 用户可见：新用户第一次启动在欢迎窗口前看到欢迎页（打开的是文档窗口时是 sheet）；老用户升级到 3.0 后第一次启动看到 What's New；Help 菜单多一项「What's New in RuntimeViewer」。
  • 可发现性：默认开启、没有开关；每个功能版本只出现一次。
  • 数据：新增 defaults 键 lastPresentedOnboardingRelease；settings.json 格式不变。删掉这个键即可让页面再出现一次。
  • 平台：只在 macOS；系统上没有 OnBoardingKit 时不弹、只记日志，App 照常启动。iOS、visionOS、Mac Catalyst 不变。
  • 发布：不需要新的 entitlement 或隐私条目，不影响公证与 Sparkle；下一个功能版本缺 What's New 时测试失败。
