摘要

工具栏「生成选项」面板的 Swift 一栏加一个勾选框「Break Long Types」，默认关闭。打开后，Swift interface 里一行放不下的类型按括号结构拆成多行——SwiftUI 视图的 typealias Body = SwiftUI.ModifiedContent<…> 不再是一行几千个字符，而是一层一层缩进展开。格式化由 MachOSwiftSection 新增的 MultilineTypeFormatting 完成，在引擎生成 interface 时对每个定义的打印各做一次；语法着色、跳转链接、注释标签与宏展开照旧。查找同时改为能跨被拆开的行定位结果。行宽固定为 100 列（不计缩进），数值存进选项、暂不给界面。

要你定

实现完成，待收尾

  1. MachOSwiftSection 推上 next 后抬 pin、合进 next（第 5、6 步）。

没问你、自己定的（可推翻）

  • 字段名 breaksLongTypes / maximumLineWidth，勾选框文字「Break Long Types」，放在「Expand Macros」下面。
  • MCP 与 CLI 的预设保持关闭；语料不格式化。
  • 只切换拆行时不重建打印器，只清 interface 缓存。

落地前提

RuntimeViewer 依赖 MachOSwiftSection 远端的 next；要先把那边正式收尾、推上 next，再抬本仓库的 pin。开发期间用本地依赖构建。

方案

  1. 选项。SwiftGenerationOptions 加 breaksLongTypes（默认关）与 maximumLineWidth（默认 100），再加计算属性 multilineTypeFormatting。.mcp 预设明确保持关闭。
  2. 引擎。RuntimeSwiftSection 存下当前的格式化设置，与打印配置一起比较，变了就清两份 interface 缓存；interface(for:) 对每个定义的打印各格式化一次再拼接；宏展开的各块不格式化（它们带着嵌套属性的 UTF-8 范围）；importedInterface(for:) 在拆 region 之前格式化。
  3. 界面。生成选项面板加勾选框；导出元数据写明这个选项。
  4. 查找。整行（或长行截出的窗口）对不上时，在去掉全部空白的正文里找：整行要恰好覆盖从某行第一个到某行最后一个可见字符的一段，窗口可以落在行中间；命中按去空白后的第几个 UTF-16 单元映射回正文。

非目标

  • 行宽不给界面（数值先存着）。
  • 语料、MCP、命令行不格式化；CLI 与 agent 插件行为不变。
  • 不改 ObjC 头文件的显示。
  • 不补导出元数据里此前就漏掉的两个选项（记为后续项）。

详细设计

选项 
@Default(false)
public var breaksLongTypes: Bool

@Default(100)
public var maximumLineWidth: Int

public var multilineTypeFormatting: MultilineTypeFormatting? {
    guard breaksLongTypes else { return nil }
    return MultilineTypeFormatting(maximumLineWidth: max(1, maximumLineWidth))
}
引擎
  • 格式化设置与打印配置一起比较；只切换拆行时只清 interface 缓存，不调用 printer.updateConfiguration，保住文件引擎的静态布局计算器。
  • 逐个定义格式化再拼接，typeUTF8Range 直接取格式化后的第一个定义；拼接只插空行，结果与整份格式化相同。
  • 格式化总在拆 region 之前，注释标签与宏归属读到的是格式化后的偏移。
查找的跨行定位
  1. 照旧找整行相同的行，取离语料行号最近的。
  2. 找不到时，语料行去掉全部空白；正文里去空白后是它前缀的行向下逐行拼接，恰好相等即为一组候选，取起始行最近的一组。
  3. 命中位置换算成去空白后的第几个字符，在候选几行里数到同一个字符得到范围；跨了插入的换行时范围包含中间的换行与缩进。

关着拆行时第一步总能找到整行，行为逐字不变。

调研

关键事实
  • 选项随 InterfaceCommand（Codable）传到 XPC 与远端引擎，新字段必须带默认值；旧对端忽略未知键。
  • MultilineTypeFormatting 不在打印配置里，引擎现有的缓存清除只看打印配置，要另存、另比、另清。
  • 查找按「整行相同」定位；语料总用 .mcp 选项一次印好存盘。
  • 成员定位、行号标尺、导出都能接受多出来的行；导出开着时同样拆开。
  • MachOSwiftSection 保证格式化只加换行与缩进、region 不变、嵌套定义取出后与单独打印一致。

替代方案

四条被否的路径
  • App 侧拿到文字后再拆：要重算注释标签与宏展开的全部偏移。
  • 放进打印配置：MachOSwiftSection 有意不这样做。
  • 语料也格式化：语料对所有选项共用、按行搜索。
  • 查找接受退化 / 行宽给界面：用户选了跨行定位、只加勾选框。

影响

  • 用户可见：面板多一个默认不勾的勾选框；勾上后放不下的类型拆成多行，导出同样拆开，查找仍定位到那一段。
  • 兼容：旧偏好解码为关闭；旧版远端引擎忽略新键、返回不拆的文字。
  • 平台与发布：不变；落地依赖 MachOSwiftSection 的 next 先推送、本仓库抬 pin。

落地步骤

  1. 选项字段与预设（已完成） —— 默认关闭、旧数据解码为关闭、派生格式化、MCP 关闭
  2. 引擎格式化与缓存失效（已完成） —— 拆开、关闭不变、切换后重生成、宏展开归属、打印器不重建
  3. 面板与导出元数据（已完成；面板未经 App 构建与人工核对） —— 勾选框、元数据一行
  4. 查找跨行定位（已完成） —— 拆开的语料行、跨插入换行的命中、取最近、拆开的长行窗口；整行优先、行中间的一段不算整行
  5. 抬依赖 pin（MachOSwiftSection 推送之后）
  6. 文档 —— 索引与状态一致
