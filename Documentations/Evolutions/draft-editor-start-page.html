摘要

编辑栏里一个空标签（新窗口、⌘T 新开的标签、用关闭按钮清空的唯一一栏）原先只显示一行灰字「Select a runtime object」。本提案照 Xcode 27.2 空编辑器显示的初始页（IDEKit 的 IDEInitialEditor）把它换成一张起始页：顶部一个大号的 Open Quickly 搜索框，输入满 3 个字符即在框下浮出匹配的镜像与对象，回车或点击打开；下面是跟着侧栏分层的最近列表（第 8 步，用户看过后要求）：侧栏停在镜像列表时是 Recent Images，列这个 Engine 最近用过的镜像；进到某个镜像后是 Recent Objects，只列这个镜像里最近在编辑栏看过的对象（图标、名字，下面一行是「Engine 〉 镜像」的路径）。每个 Engine 记 10 个镜像、每个镜像记 10 个对象，默认显示 8 行、可 Show All 展开，双击或回车打开。最近列表按 Engine 存盘、跨启动保留。读文件时的「Reading …」占位不变。File › Open Quickly…（⇧⌘O）的浮动条改成与起始页同一个搜索（用户看过初版后要求），从 1 个字符起就搜，有文档窗口时总可用；侧栏原来只搜当前镜像的那一份 Open Quickly 删掉。App 级的欢迎窗口由另一会话负责，不在本提案范围内。

要留意

没有询问就采用的假设（看效果时可以推翻）

  • 最近列表跟着侧栏分层（用户定的）：侧栏的镜像列表相当于 Xcode 欢迎窗口那一层，进到一个镜像相当于打开一个项目；标题因此是「Recent Images」与「Recent Objects」，而不是 Xcode 的「Recent Files」。搜索框不分层。重开对象时按它自己的语言显示。
  • 「用过一个镜像」算三种：侧栏进到它、在镜像页看它、看它的一个对象。打开最近镜像显示镜像页，侧栏不动。
  • 最近列表按 Engine 记，镜像与每个镜像的对象各以 10 为上限，镜像被挤出时连同对象一起丢；没有清空按钮；跟着存储实时刷新。镜像路径按 Engine 的规范写法记，模拟器进程也对得上。
  • 路径行写「Engine 名 〉 镜像名」，图标是 Engine 的图标。
  • 存下来的对象不带 children；已有标签显示同一对象时用那个标签里的形态打开。
  • 搜索框的范围是整个 Engine（镜像名 + 已索引镜像的对象），不跟着侧栏当前镜像；⇧⌘O 的浮动条用同一个搜索，但照 Xcode 的窗口从 1 个字符起搜（只有起始页要满 3 个）。
  • ⇧⌘O 的行与起始页的相同（图标、名字、路径行），选中的打开在焦点栏，⌥ 下一栏、⇧⌥ 新标签，与侧栏点击一致。
  • 结果板盖在最近列表上、浮在框下；结果行 56 高。页面背景沿用内容区原来的背景。

已知、未在本提案处理

  • 第一次搜索会读这个 Engine 所有已索引镜像的对象列表，不封顶；开了 Always Index 或索引了大半个 shared cache 时第一次会慢。
  • AppDefaults 的文件存储不分 Debug 与发布版，同时开着会互相覆盖最近列表；用过的 Engine 键不清理。
  • 一次搜索期间目录不刷新，期间新索引的镜像要清空输入框再搜（SP.5）；挂起回车期间方向键选的是旧结果（SP.8）。
  • 同一窗口先后用起始页的框与 ⇧⌘O，会各读一份目录（SP.12）；浮动条按词核对结果、切换 Engine 后核对结果来源这两处没有自动测试（SP.13、SP.15）。
  • 最近列表变空而焦点在列表上时，焦点留在被隐藏的列表上（SP.18）；第 2–7 步写的旧存储文件不迁移，最近列表从空开始。
  • 界面目视（布局、颜色、焦点、结果板、⇧⌘O 浮动条的行、两种标题）与 macOS 27 上的点击取焦点没有在 App 里实测。

起始页的 VM 与 ⇧⌘O 浮动条的 VM 各持有一个 OpenQuicklySearch，按需读引擎的搜索目录；起始页另读存储里本 Engine 的最近镜像，侧栏在镜像列表时列镜像、在镜像里时列这个镜像的对象，记录器跟着 DocumentState 写存储。侧栏那一份 Open Quickly 整个删掉。

the focused pane shows an object or an image page, the sidebar goes into an image
  → DocumentState.$selectedRuntimeObject / $editorArea / $currentImageNode
  → RecentRuntimeImagesRecorder → RecentRuntimeImages.recording(_:in:) / recordingImage(at:in:)
       [entries under the image's other spelling folded in first; no other entry respelled]
  → AppDefaults.recentRuntimeImagesByEngine[engineKey]
  → ContentPlaceholderViewModel (every empty pane of every window on the engine)
       + $currentImageNode: nil → Recent Images; an image → that image's Recent Objects
  → rows → ContentPlaceholderViewController

typing in the start page's field (3 characters or more)
  or in the ⇧⌘O bar (1 character or more)
  → OpenQuicklySearch.matches(for:limit:)   [nothing read while the engine lists no image]
  → OpenQuicklyCatalog.load(imagePaths:from:)   [once per search, 8 images at a time]
  → OpenQuicklyCatalog.matches(for:limit:) → FilterEngine + OpenQuicklyRanking
  → results → Return (the page waits for the newest results; the bar takes its current term's) / click
  → .focusEditorPane(paneID) → .open(shownForm ?? object, in:) | .openImage(path, in:)

search ends: field emptied, page starts over, bar closed, item opened, engine switched
  → the term still being answered is dropped → OpenQuicklySearch.end()

提议方案

三块内容与最近列表怎么记
  1. Open Quickly 搜索框：页面顶部居中的大号圆角框，尺寸、底色与光环照 Xcode。满 3 个字符后，框下 5pt 浮出圆角结果板（Liquid Glass，macOS 26 之前半透明材质），只在搜索框聚焦且窗口为 key 时显示。搜这个 Engine 的全部镜像（按文件名）与已索引镜像里的对象（含嵌套的），不为搜索触发索引；第一次满 3 个字符时读目录、同一次搜索复用、结束即丢。少于 3 个字符时不更新查询、上一次查询照常完成；框清空时结果清掉。↑ / ↓ 移动选中，回车打开（最新结果还没到时等它到），Esc 清空；⌥ 下一栏、⇧⌥ 新标签。
  2. 最近列表（第 8 步起跟着侧栏分层）：侧栏在镜像列表时标题「Recent Images」，列最近用过的镜像（打开是镜像页）；侧栏进到一个镜像后标题「Recent Objects」，只列这个镜像的最近对象。.title 字体的标题，多于 8 行时右侧有 11pt 强调色的「Show All」/「Show Less」，侧栏换层级或换镜像时关掉；对象行是图标、名字与「Engine 名 〉 镜像名」路径；单击只选中，双击或回车打开；列表从键盘取得焦点且没有选中时选中第一行。
  3. 读文件时：照旧转圈加「Reading “…”…」，读完回到起始页。

每个文档在 DocumentSession.open() 里起一个记录器。侧栏进到一个镜像、焦点栏显示它的镜像页或它的一个对象，都把这个镜像移到 Engine 的镜像列表最前；显示的对象还移到它所在镜像的对象列表最前（按身份去重、换形态不算再看一次）。镜像与每个镜像的对象各最多 10 个，镜像路径按 Engine 的规范写法记（之前按另一种写法记下的同一镜像，在下一次记录它时合并进来，别的项不改写），写进 AppDefaults.recentRuntimeImagesByEngine。一栏只有一个起始页，所以换到另一个标签或页面重新放进栏里时都从头开始。只在 macOS 记。

⇧⌘O（第 6、7 步）：File › Open Quickly… 的浮动条（UIFoundation 的 QuickActionBar）挪到窗口一层，与起始页用同一个 OpenQuicklySearch，从 1 个字符起搜、只收下当前这个词的结果；行与起始页的相同，选中的打开在焦点栏。侧栏原来那一份连同它的按需物化机制删掉。

非目标：App 级欢迎窗口；改 ⇧⌘O 浮动条的外观；Engine 端按名字找对象或为搜索触发索引；最近列表的右键菜单、移除、清空、拖出与 Xcode 的错误横幅；iOS、visionOS；C++ 对象。

详细设计

最近列表、行、ViewModel 与搜索的接口 
public struct RecentRuntimeImage: Codable {   // canonical image path + its recent objects
    let imagePath: String
    let objects: [RuntimeObject]
}

struct RecentRuntimeImages {                  // one engine's list, keyed as Always Index keys engines
    static let maximumImageCount = 10, maximumObjectCountPerImage = 10

    func objects(ofImageAt:in:) -> [RuntimeObject]

    func recordingImage(at:in:) -> [String: [RecentRuntimeImage]]?
    func foldingOtherSpellings(of:in:canonicalImagePath:) -> [String: [RecentRuntimeImage]]?

}

struct OpenQuicklyCatalog {
    static func load(imagePaths: [String], from engine: RuntimeEngine) async -> OpenQuicklyCatalog

打开：先 .focusEditorPane(editorPaneID)，再 .open(formOnScreen(of: object), in:) 或 .openImage(path, in:)。formOnScreen(of:) 按身份（不论语言）先在焦点栏、再按布局顺序找正显示这个对象的标签，取那里的形态。回车在最新查询的结果到达前挂起，文字再变就作废。

调研与 Xcode 的度量

现状代码与 IDEKit 27B52 里读出的数值
  • 空标签由 ContentCoordinator.enterPlaceholderScene() 显示 ContentPlaceholderViewController，每栏懒建一份；原先的 Open Quickly 只搜侧栏当前镜像，侧栏在镜像列表根上时不可用。
  • 页面：内容列居中，200–700 宽，两侧 32，顶部 80；搜索框与最近一节之间 65；标题与列表间 12。
  • 搜索框：高 47、连续圆角 24；未聚焦填 WelcomeListCellBackground（浅色 0.373 灰 α 0.12，深色白 α 0.04）；聚焦且 key 时去底色、画 3pt 强调色描边（0.6，一半在外）；放大镜在 x = 16 起的 32 × 32 框里，文字从 62 起，20pt medium。
  • 输入：满 3 个字符才写进查询（写死的 3）；结果板框下 5pt、行 56、高 min(行数 × 56, 420) + 20、0.25 秒缓动。
  • 最近一节：defaultRowCount 8；Show All / Show Less 11pt 强调色；行图标位 32 × 32、名字 13pt、路径 11pt 次要色、路径图标 12 × 14、段间 chevron.compact.right；单击只选中，双击或回车打开；工作区最近文档最多 10 条。

替代方案

四条被否的路
  • 框只作入口、点一下弹出现有的浮动 Open Quickly：新窗口里不可用，也不像 Xcode。
  • 只搜侧栏当前镜像：新窗口里什么也搜不到。
  • 给 Engine 加按名字找对象的命令、或先索引全部镜像：范围大，且不该因打字触发索引；列为后续项。
  • 最近列表只记本窗口、或另起一对页面类：前者新窗口永远是空的，后者要在协调器里多一个场景。

影响

  • 用户可见：空标签显示起始页；新增按名字找镜像与已索引对象、回到最近看过的对象。⇧⌘O 改为搜整个 Engine、从 1 个字符起、有文档窗口时总可用，行与起始页相同；侧栏（除了不再有自己的 Open Quickly）、读文件占位、Load Frameworks 页不变。
  • 数据：新增 AppStorage/recentRuntimeImagesByEngine.json，读不出当空，旧版本忽略它。第 2–7 步写的 recentRuntimeObjectsByEngine.json 从未发布，不迁移。
  • 平台：只在 macOS 15+；iOS、visionOS 不变。发布：无新权限，不影响公证与 Sparkle。

落地步骤

  1. 起始页骨架（已完成）：页面、行模型、镜像行路径、editorPaneID。
  2. 记录最近对象并列出（已完成）：记录规则、记录器、存储、本 Engine 的列表。
  3. Show All 与打开最近对象（已完成）：8 行与按钮、双击与回车、沿用标签里的形态、页面复位、点击取焦点。
  4. Open Quickly 搜索框（已完成）：目录、共用排序、搜索与按键、结果板、Xcode 外观、焦点。
  5. 文档（已完成）：AGENTS.md、术语表、索引、自审裁决。
  6. ⇧⌘O 与起始页同一个搜索（已完成）：OpenQuicklySearch、浮动条的 VM、命令挪到窗口、共用的行视图；结束搜索时丢掉还在作答的词、核对结果来自哪个 Engine、镜像树为空时不读。
  7. 删掉侧栏自己的 Open Quickly（已完成）：输入输出、按需物化、专测与文档段落；侧栏其余行为不变。
  8. 最近列表跟着侧栏分层（已完成）：存储改为最近镜像各带最近对象；侧栏在镜像列表时列镜像、在镜像里列这个镜像的对象，标题跟着变，换层级关掉 Show All；路径按规范写法记与合并；搜索框不分层。

每步过行为测试（先红后绿，另做变异检查）与两位审查者的审查；只能在界面上看到的行为列为目视，未在 App 里实测。

后续项

  • AppDefaults 的文件存储按版本分目录。
  • 清理不再用的 Engine 键的最近列表。
  • 搜索没索引的镜像里的对象（Engine 端按名字找对象）。
  • 最近列表的右键菜单、移除、清空、拖出；Xcode 的错误横幅与空页样式。
  • 最近列表变空时焦点留在被隐藏的列表上（SP.18）。
  • 路径栏的镜像节点表在 Engine 问到模拟器根路径之前建好时不重算（基线上就有）。
  • Engine 问到模拟器根路径时发通知，起始页与路径栏立即重算（SP.17）。
