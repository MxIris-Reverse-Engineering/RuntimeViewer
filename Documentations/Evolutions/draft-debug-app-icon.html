摘要

Debug 与 Debug-arm64e 构建出来的 App（RuntimeViewer-Debug.app、RuntimeViewer-Debug-arm64e.app）改用一份新图标 Resources/AppIconDebug.icon：主图标原样照搬，右下角叠一个和 BETA 同款的黑底白字角标，写「DEBUG」。画法完全照 BETA 角标——同一个胶囊外形（两端圆头保持 Xcode 的原曲线，只按字长伸缩直边）、同样的颜色与图层组设置、同一个位置（右边缘与底边对齐 BETA）。角标的两层 SVG 由现有的 CATALYST 角标脚本生成，脚本改为按「角标预设」生成，CATALYST 的输出逐字节不变。Xcode 26 变体照 0020 的机制生成。Release 构建与 beta 渠道的图标不变。

动机：开发时常同时开着发布版和自己编的 Debug 版，两者图标完全相同，Dock、⌘-Tab、Finder、欢迎窗口里分不出哪个是哪个。项目已有 BETA（beta 渠道）与 CATALYST（Catalyst helper，0028）两个「主图标加角标」的先例，DEBUG 照同一套画法。

要你定

批准之后、动手第一步时再定

  1. DEBUG 的字高：渲染 136（BETA 原值）、120、108 三档给你挑，选定后写进预设。

没问就采用的假设

  • 颜色照 BETA 的黑底白字，不换成别的颜色。
  • 只给 macOS App 的 Debug / Debug-arm64e 配置；Catalyst helper 与 iOS 系 App 不加。
  • beta 渠道仍优先：用 Debug 配置做 beta 归档演练时出 BETA 图标。

详细设计

生成脚本的预设 
struct BadgePreset {
    let word: String
    let capHeight: CGFloat
    // In BETA's units, scaled by capHeight / 136.
    let leadingPadding: CGFloat
    let trailingPadding: CGFloat
    // <prefix>Lozenge.svg and <prefix>Wordmark.svg
    let fileNamePrefix: String
}

let badgePresets: [String: BadgePreset] = [
    "catalyst": BadgePreset(word: "CATALYST", capHeight: 96, leadingPadding: 71.5, trailingPadding: 71.5, fileNamePrefix: "Catalyst"),
    "debug": BadgePreset(word: "DEBUG", capHeight: /* picked from the renders */ 120, leadingPadding: 79, trailingPadding: 64, fileNamePrefix: "Debug"),
]

胶囊宽度 = 墨迹宽 + (左留白 + 右留白) × 缩放比；字的横向位置 = 胶囊左缘 + 左留白 × 缩放比 − 墨迹左缘。左右留白相等时与原来的居中公式数学上相同，CATALYST 的输出应逐字节不变，用 git diff --exit-code 验证。

swift Resources/AppIconTools/GenerateBadgeLayers.swift catalyst "RuntimeViewerUsingAppKit/RuntimeViewerCatalystHelper/CatalystHelperIcon.icon/Assets"
swift Resources/AppIconTools/GenerateBadgeLayers.swift debug "Resources/AppIconDebug.icon/Assets"
AppIconDebug.icon/icon.json 与 AppIconBeta 的差别 
"image-name" : "BetaWordmark.svg"  ->  "DebugWordmark.svg"
"name"       : "Beta Wordmark"     ->  "Debug Wordmark"

ArchiveScript.sh 的推导 
APP_ICON_BASE_NAME="AppIcon"
if [[ "$CHANNEL" == "beta" ]]; then
    APP_ICON_BASE_NAME="AppIconBeta"
    MAIN_APP_XCODEBUILD_SETTINGS+=("RUNTIME_VIEWER_APP_ICON_BASE_NAME=$APP_ICON_BASE_NAME")
elif [[ "$CONFIGURATION" == Debug* ]]; then
    # Debug.xcconfig picks the DEBUG-badged icon, and Debug-arm64e includes it.
    APP_ICON_BASE_NAME="AppIconDebug"
fi

只改推导、不传覆盖：图标由 xcconfig 决定，脚本独立复述一遍，两处对不上就归档失败。

验证
  • ictool 渲染 Default / Dark / Tinted，512 与 64 像素，与 AppIconBeta.icon 并排比较；字高候选 136 / 120 / 108 各一张。
  • 到 Ultra 上：三个配置的 -showBuildSettings 解析出 AppIconDebug / AppIconDebug / AppIcon；Xcode 27 与 26.6 的 actool 以绝对路径编两份新文档；TuistScript.sh check 通过；Tuist workspace 编一次 Debug App，CFBundleIconName 是 AppIconDebug。

调研

查证过的事实
  • Shared.xcconfig:11 用 RUNTIME_VIEWER_APP_ICON_NAME；Debug.xcconfig:30-32 与 Release.xcconfig:33-35 各自定义基名 AppIcon；Debug-arm64e.xcconfig include Debug.xcconfig、不覆盖图标；INCLUDE_ALL_APPICON_ASSETS = NO。
  • Tuist 的三个配置引用同名 xcconfig（Project.swift:71-83），资源清单在 Project.swift:157-162。
  • 原生工程资源条目在 project.xcproj:51-54（Xcode 27 新格式）；本会话没有 Xcode MCP，xcrun xcodeproj 写入会改坏工程，所以手工加两行。
  • BETA 角标组：两层、平移 (-33, 40)、折射 0.07 / 0.39、半透 0.42、阴影 neutral 1；四组已是 actool 上限，DEBUG 文档也是四组。
  • CatalystHelperIcon.icon 的角标组与 BETA 的只差两层的 image-name 与 name。
  • CATALYST 脚本：SF Pro 半窄体 Black（量 BETA 得 424，Xcode 原版 426），胶囊按 BETA 缩放、直边伸缩，右缘 929、底边 898；留白 71.5 是 BETA 左 79 右 64 的平均，原注释说 79 / 64 是给 B 的直竖笔的补偿——D 同样是直竖笔，所以 DEBUG 用 79 / 64。
  • ArchiveScript.sh 支持 --configuration Debug，图标校验会因 AppIconDebug 误报，要跟着改推导。
  • 没有代码按名字取 App 图标（git grep 查过）。
  • 推测：按 BETA 的 136 字高，DEBUG 角标约 700 × 260，可能过大；待渲染确认。

替代方案

5 条，均放弃
  • 用颜色区分：换主色在深色外观下分不出（0028 试过）；换角标颜色可行，但要求照 BETA 画法，先保持黑底白字，渲染后觉得难分再改两个 fill。
  • 复制一份 Debug 专用脚本：九成重复，改画法要改两处。
  • 原名加参数：文件名与用途不符；改名后 0028 里是历史路径，提案是快照不回改。
  • 用 Xcode 原版 B、E 拼 DEBUG：D、U、G 没有原版轮廓，混用不协调。
  • 命令行覆盖图标名：Debug 构建多来自 Xcode 界面和 RunScript.sh，没有统一入口。

影响

  • 只影响自己编 Debug / Debug-arm64e 的开发者：Dock、⌘-Tab、Finder、欢迎窗口里带 DEBUG 角标。Release 与 beta 渠道不变。
  • 不涉及设置与缓存；系统图标缓存可能让旧 Debug 版暂时显示旧图标，重启 App 或 Dock 即更新。
  • 平台与最低版本不变；无新权限、entitlement；公证与 Sparkle 不受影响，Release 包不变大。
