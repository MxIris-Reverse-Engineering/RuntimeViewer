摘要

运行时对象前面的 Xcode 风格字母图标（橙色 C、紫色 Pr、蓝色 Ex……）目前由 UIFoundation 的 IDEIcon 画，它是开源项目 ide-icons 的移植，形状、字体和留边都不是 Xcode 的。本提案把唯一的渲染器 IDEIconRuntimeObjectIconRenderer 换成用 AppKitPlus 的 NSIcon（Xcode 27 DVTGeneratedIconSpec 的复刻）画，macOS 与 iOS / visionOS 共用同一份代码——iOS 一侧经 AppKitPlus-Release 同包发布的 UIKitPlus 拿到同名的 NSIcon。Xcode 图标尺寸（16pt 及以下）的框里底板铺满，与 Xcode 同一位置一样大；更大的框（侧栏 18、检查器 20、起始页与 iOS 列表 24）四周留 1pt，底板保持以前的大小。图标照旧作为一张图片交给各个视图，选中行的样子不变；随后去掉 UIFoundation 的 IDEIcons trait。

AppCore 只选字形，AppUI 的渲染器把字形画成图片；live 渲染器从 IDEIcon 换成 NSIcon，macOS 取 AppKitPlus、iOS 与 visionOS 取 UIKitPlus 里的同名类型。

一个字形画成图片的调用链：

cell view: appearance.primaryIcon?.image            (IconDescriptor.glyph)
└── RuntimeObjectIcon.image(for: glyph)
    └── NSIconRuntimeObjectIconRenderer.image(for:)
        └── RuntimeObjectIconImageCache.image(for:drawing:)     (first time only)
            ├── NSGeneratedIconSpecification(letters: glyph.text, shape: .squircle,
            │                                backgroundColor: NSIconColor(glyph.color).color, glyphColor: nil)
            ├── NSIcon(generatedIconSpecification:)
            ├── glyph.size <= 16 (Xcode's icon sizes): the plate fills the image
            │   └── .simple            → icon.image(of: CGSize(width: glyph.size, height: glyph.size))
            │       .simpleHighlighted → icon.highlightedImage(of: …)
            └── glyph.size > 16 (RuntimeViewer's own frames: 18, 20, 24): 1pt of room on each side
                ├── macOS          → NSImage(size: glyph.size, drawingHandler:)
                │                    └── draws icon.image(of: glyph.size - 2) inset by 1pt, at each draw
                └── iOS, visionOS  → UIImageAsset of 4 variants (light / dark × normal / high contrast)
                                     └── each: icon.image(of: glyph.size - 2, compatibleWith: variant)
                                         drawn inset by 1pt with UIGraphicsImageRenderer

详细设计

新渲染器、留边与颜色映射 
#if os(macOS)
import AppKit
import AppKitPlus
#else
import UIKit
import UIKitPlus
#endif

final class NSIconRuntimeObjectIconRenderer: RuntimeObjectIconRendering {
    // The largest frame an icon fills: Xcode's code symbol icons are this size and smaller.
    static let largestFilledFrameSize: CGFloat = 16
    // The room a larger frame keeps on each side of its icon.
    static let margin: CGFloat = 1

    private let imageCache = RuntimeObjectIconImageCache()

    func image(for glyph: RuntimeObjectIcon.Glyph) -> NSUIImage {
        imageCache.image(for: glyph) { glyph in
            let specification = NSGeneratedIconSpecification(
                letters: glyph.text, shape: .squircle,
                backgroundColor: NSIconColor(glyph.color).color, glyphColor: nil)
            let icon = NSIcon(generatedIconSpecification: specification)
            let isHighlighted = glyph.style == .simpleHighlighted
            let frameSize = CGSize(width: glyph.size, height: glyph.size)
            guard glyph.size > Self.largestFilledFrameSize else {
                return Self.image(of: icon, size: frameSize, isHighlighted: isHighlighted)
            }
            let iconSize = CGSize(width: glyph.size - 2 * Self.margin, height: glyph.size - 2 * Self.margin)
            return Self.image(of: icon, size: iconSize, isHighlighted: isHighlighted, centeredInFrameOf: frameSize)
        }
    }

    private static func image(of icon: NSIcon, size: CGSize, isHighlighted: Bool) -> NSUIImage {
        isHighlighted ? icon.highlightedImage(of: size) : icon.image(of: size)
    }

    #if os(macOS)
    // Draws NSIcon's image each time it is drawn itself, so the icon takes the appearance it is drawn in.
    private static func image(of icon: NSIcon, size iconSize: CGSize, isHighlighted: Bool, centeredInFrameOf frameSize: CGSize) -> NSImage {
        let iconImage = image(of: icon, size: iconSize, isHighlighted: isHighlighted)
        return NSImage(size: frameSize, flipped: false) { frame in
            iconImage.draw(in: frame.insetBy(dx: (frame.width - iconSize.width) / 2, dy: (frame.height - iconSize.height) / 2))
            return true
        }
    }
    #else
    // One image for each appearance NSIcon draws an icon for (light / dark × normal / high contrast),
    // at the current trait collection's scale (2 when it has none), gathered in a UIImageAsset.
    private static func image(of icon: NSIcon, size iconSize: CGSize, isHighlighted: Bool, centeredInFrameOf frameSize: CGSize) -> UIImage { … }
    #endif
}

extension NSIconColor {
    init(_ color: RuntimeObjectIcon.Glyph.Color) {
        switch color {
        case .blue: self = .blue
        case .brown: self = .brown
        case .gray: self = .gray
        case .green: self = .green
        case .orange: self = .orange
        case .pink: self = .pink
        case .purple: self = .pinkishPurple   // systemPurple
        case .red: self = .red
        case .teal: self = .teal
        case .yellow: self = .yellow
        case .indigo: self = .purple          // systemIndigo
        case .mint: self = .ocean             // systemMint
        case .cyan: self = .coreML            // systemCyan
        }
    }
}
  • RuntimeObjectIconImageCache 不动：NSIcon 自己的图片缓存只在图片还被用着时有效，「同一字形永远同一对象」仍由 RV 的缓存负责。
  • Glyph.Style 剩 .simple 与 .simpleHighlighted，名字不改，免得牵动公开函数的默认参数。
  • Glyph.Color 剩 13 个值，monochrome 删去。

调研

现状代码、上游能力与验证过的事实

现状

  • AppCore 只选字形（RuntimeObjectIcon.Glyph），AppUI 经 runtimeObjectIconRendering 画；live 值是 IDEIconRuntimeObjectIconRenderer，test 值是画空白图的 BlankRuntimeObjectIconRenderer，两者都经 RuntimeObjectIconImageCache 保证同一字形同一图片。
  • 全仓库用到 IDEIcon 的只有这个渲染器、它的测试和 Package.swift 的 "IDEIcons" trait；渲染器没有平台条件，iOS 今天也是它在画。
  • 生产代码只用 .simple 样式；.default、.outline、.simpleHighlighted、.monochrome 只出现在映射与测试里。
  • 图标框：macOS 默认 18pt、iOS 24pt；跳转栏、Find、来源弹窗、历史菜单 16pt；References 页 14pt。

上游（AppKitPlus 0.24.0）

  • NSGeneratedIconSpecification(letters:shape:backgroundColor:glyphColor:)，.squircle 即 Xcode 代码符号图标的形状。
  • NSIcon(generatedIconSpecification:)；image(of:) 铺满给定尺寸，highlightedImage(of:) 是白底镂空的选中图；线程安全。
  • NSIconColor 的 .blue 等就是同名系统色，.pinkishPurple = systemPurple、.purple = systemIndigo、.ocean = systemMint、.coreML = systemCyan；IDEIcon 的 .simple 用的正是这些系统色。
  • UIKitPlus 与 AppKitPlus 编同一批源文件，Swift 名字完全相同，只有模块名不同；动态 framework，支持 iOS 17、visionOS 1，不支持 tvOS 与 Mac Catalyst；0.24.0 首发，RV 下限正是 0.24.0。

验证过的

  • IDEIcon 的 .simple 在框内留 1pt 边；NSIcon.image(of:) 不留边。
  • IDEIcon 在 iOS 上画成固定颜色的 CGImage 并被永久缓存，不随深浅色切换。
  • 越狱版打包脚本按目录找内嵌 framework，多一个 UIKitPlus.framework 不用改脚本。

推测，实现时核对

iOS 上渲染器在 cell 配置时于主线程调用，UITraitCollection.current 是主屏的 trait，image(of:) 按主屏倍率出图；若在 3x 机型上发糊，再按窗口场景的 displayScale 处理。

替代方案

6 条，均已否
  • 所有尺寸都铺满：最初选的就是它，实现后又改掉了。用户看过后觉得侧栏等处的图标变大了：18pt 框里底板从 16pt 变成 18pt，字母还按 Xcode 的字号表从 12pt 跳到 14pt（16pt 图标对应 11pt）。
  • 所有尺寸都留 1pt 边（IDEIcon 的做法）：Find、跳转栏这些照 Xcode 取 16pt 框的地方，铺满才和 Xcode 一样大。留边要按平台各写一段画图代码，iOS 一侧照 NSIcon 的做法把四种外观各画一张、重新收进 UIImageAsset，才不丢深浅色。
  • 铺满并把默认尺寸 18 改 16：侧栏图标框变窄、标题左移，牵动所有用默认尺寸的布局。
  • 连同选中反白一起做（NSIconView）：改动面是十几个 cell 与 iOS 的选中处理，留作以后单独做。
  • 用 NSIcon.codeSymbolIcon(named:) 现成图标：Xcode 的类一律紫色，与 RV 用颜色区分语言的做法冲突。
  • 让 UIFoundation 的 IDEIcon 改用 NSIcon 实现：要先改上游并发版，而 RV 只需换自己的渲染器。

影响

用户可见变化

  • 所有运行时对象的字母图标改成 Xcode 的样子：连续圆角的 squircle、SF Pro Rounded 字母，颜色不变。
  • 侧栏与特化选择器（18pt）、检查器（20pt）、起始页与 iOS 列表（24pt）里底板与以前一样大，四周照旧留 1pt；18pt 框里字母按 Xcode 的字号表取 11pt（以前 12pt）。
  • Find、跳转栏、来源弹窗、历史菜单（16pt）与 References 页（14pt）里底板铺满，比以前大 2pt，与 Xcode 同一位置一样大。图标框本身与行布局不变。
  • iOS / visionOS 上图标随系统深浅色切换。
  • 选中行里的图标样子不变。

落地步骤

  1. 登记提案——两份索引。
  2. 换上新渲染器，删掉 IDEIcon（已完成）——UIKitPlus 依赖与 trait、锁文件的 originHash、新渲染器与新测试、live 值、旧渲染器与旧测试、Glyph 的三个无用值、两处注释。原计划分两步：新渲染器的 switch 要穷尽 Glyph，三个无用值不删就编不过，删了旧渲染器又编不过，所以合成一步。行为：13 种颜色各自画在同名系统色上；两种样式与 NSIcon 的输出逐字节相同；14、16、18、24pt 的图片四条边的中点都是底板（第 3 步改为只对 14、16pt 成立）；live 值是新渲染器。构建：macOS 包测试通过，iOS 与 visionOS 的 App 编译通过。
  3. 文档（已完成）——两份子目录 AGENTS.md 与根 AGENTS.md 的依赖下限。
  4. 大于 16pt 的框留 1pt 边（已完成）——渲染器、测试与 Sources/AGENTS.md。行为：14、16pt 的图四条边中点都是底板；18、20、24pt 的图尺寸等于框，2x 位图里四条边向内的头两个像素透明、第三个起是底板；18pt 的图中间与 16pt 的 NSIcon 主图、选中图逐像素一致；留边的图在浅色、深色外观下各自与 16pt NSIcon 一致（改成只画一次的位图时这条失败）。构建：macOS 包测试通过；iOS 与 visionOS 的 App 编译通过，iOS 一侧的绘制没在设备或模拟器上看过。
