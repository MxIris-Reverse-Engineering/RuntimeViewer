摘要

iOS 版（RuntimeViewerUsingUIKit，iPhone 与 iPad）的内容区从 UITextView 换成重建版 SourceEditor 的 UIKit 版，和 macOS 一样经 RuntimeViewerSourceEditorBridge 驱动。重建版的 UIKit 层只发在 26.6 线上，所以 iOS 单独钉 26.6.10（新的 PinnedRelease-iOS.txt，框架下载到 Frameworks-iOS/<平台>/），macOS 留在 27.2.0-alpha.2 不动。

桥接框架从只编 macOS 改为 macOS、iOS 真机、iOS 模拟器三处都编：平台无关的逻辑（语义着色、同名高亮、阅读位置）两边共用，视图层 iOS 另写一个 UIKitSourceEditorBridge。第一版在 iOS 上提供语法与语义着色、设置里的主题、行号、小地图、MARK 分隔线、插入点、同名高亮、系统查找（导航栏的放大镜按钮与 ⌘F）和回到上次读到的位置；Settings › Editor 页在嵌了框架的 iOS 版上出现，只列这几项。

越狱版（arm64e，框架没有这个切片）、visionOS（上游不支持）和没下载到框架的检出照旧用 UITextView。点击跳转、注释标签与折叠、行内展开不在这一篇。

动机：iOS 的内容区还停在早期 Mac 版的水平（没有行号、小地图、查找、同名高亮、阅读位置）；重建版的 0014 / 0015 已经给 26.6 线加上 UIKit 层并带 iOS 切片；macOS 桥接里的语义着色、声明解析短路、同名高亮只依赖共享框架类型，在 UIKit 下能原样编译。完整动机见愿景《iOS 功能对齐》。

提议方案

版本与下载

  • iOS 单独一个 pin：PinnedRelease-iOS.txt，格式同 PinnedRelease.txt，钉 26.6.10 与四个框架（SourceEditor、SourceModel、SourceModelSupport、_CodeCompletionFoundation；桥接不用 SourceEditorRegExSupport）的 SHA-256，取自 26.6.10 的 Package.swift。macOS 的 pin 不动；等 27 线有了 UIKit 再合成一个（后续项）。
  • iOS 的框架放 Frameworks-iOS/：iphoneos/（ios-arm64）、iphonesimulator/（ios-arm64-simulator），加标记文件 PinnedRelease-iOS.txt。子目录用 PLATFORM_NAME 的值命名。macOS 的 Frameworks/ 布局不变，所以 macOS 的搜索路径、测试 rpath、ArchiveScript.sh 的核对都不用改。
  • FetchSourceEditorScript.sh 加 --platform macos|ios|all，默认 all，每个平台独立跳过与替换。RunScript.sh、TuistScript.sh 传 macos；ArchiveScript.sh 带 --include-ios-simulator 时取 all、取不到就停；release.yml 取 all。
  • UpdateSourceEditorScript.sh 加 --platform macos|ios（默认 macos），按所选 pin 的大版本线取最新：iOS 停在 26 线、macOS 停在 27 线。
  • EmbedSourceEditorFrameworks.sh 按 PLATFORM_NAME 选 pin 与来源；iOS 框架是浅层 bundle，ditto 与 codesign 照常用，没签名身份就不签。

桥接框架改成双平台

  • xcconfig：SDKROOT = auto、SUPPORTED_PLATFORMS = macosx iphoneos iphonesimulator、IPHONEOS_DEPLOYMENT_TARGET = 18.0；搜索路径按 SDK 分开、都只给 arm64；iOS 的 runpath @executable_path/Frameworks @loader_path/Frameworks。macOS 的值一个不改。
  • 守卫照旧 #if arch(arm64) && canImport(SourceEditor)：模拟器通用构建的 x86_64 与 macOS 的 Intel 切片一样编空。只在 macOS 用的文件再加 #if os(macOS)，只在 iOS 用的加 #if os(iOS)。
  • 公开协议 SourceEditorBridging 按平台声明：同名成员、不同平台类型的各写一份；只有 macOS 能做的整个包进 #if os(macOS)。不引入新的公开别名，macOS 的调用点一行不改。
  • iOS 的视图层是新类 UIKitSourceEditorBridge，用 ReadOnlySourceEditorView（压住软键盘的子类）做编辑器视图。Swift 不允许一个模块里有两个同名源文件，所以与 macOS 的 SourceEditorBridge 不同名。SourceEditorBridgeFactory 按平台选。
  • 四个逻辑文件两边共用；ReadingStateCache 改成按存储状态泛型。

App 这边

  • 两端共用的值下沉到 AppUI：SourceEditorThemeConversion 搬到 RuntimeViewerAppUI/Theme/；新增 SourceEditorSourceDescription。macOS 的控制器改用它。
  • 只有 iOS target 接入：跨工程依赖桥接、两个 embed phase、ENABLE_USER_SCRIPT_SANDBOXING = NO、编译条件 RUNTIME_VIEWER_SOURCE_EDITOR。新文件放在共用的 synchronized folder 里、整个包在这个条件中；越狱版与 visionOS 编出来是空文件。不用 canImport(RuntimeViewerSourceEditorBridge)：越狱版与 iOS 版同在 Debug-iphoneos 产物目录，会 import 到却链接失败。
  • iOS 的 ContentSourceEditorViewController（UIKitViewController<ContentTextViewModel>）：output.interface → SourceEditorSourceDescription → setSource → interfaceDisplayed；ContentTextRenderer.theme → 主题字典（按 traitCollection.userInterfaceStyle 取内置的深浅主题作底）；observe settings.editor → applyDisplayOptions(from:)；导航栏右侧放大镜按钮 → showFindInterface(query: "", pattern: .contains, isCaseSensitive: false)。
  • iOS 的 SourceEditorBridgeProvider 与 SourceEditorBridging+Settings 各写一份，只做可用性、建桥与取内置主题，不做小地图预热。

设置

  • SourceEditorFrameworks 放开平台限定，iOS 看 privateFrameworksURL 下的浅层 bundle；路径拼法写成按布局参数化的纯函数。
  • EditorSettingsView 在 iOS 上也编，只列行号、小地图、MARK 分隔线、插入点四项。
  • iOS 的 SettingsViewController 在框架可用时加「Editor」页，否则不加。

非目标

  • 点击跳转（iOS 没有跟随 SelectionRoute 的代码，属于愿景第四、五步）。
  • 注释标签与折叠、C 导入类型名的行尾标签（iOS 的 ContentTextViewModel 不取注释结构；折叠在 UIKit 版里没有）。
  • 行内展开、吸顶标题、缩进参考线、折叠条（UIKit 版没有）。
  • 不可见字符（要自带 SF Mono，涉及字体授权）。
  • 越狱版与 visionOS；iOS 上的右键与长按菜单、交叉引用。
  • macOS 的任何行为变化、合成一个 pin、Tuist 覆盖 iOS 工程、修 iOS 的 Transformer 设置不生效（后续项）。

调研

1. 重建版的 UIKit 版在哪条线、带什么切片
  • UIKit 层由重建版 0014 加在 main（26.6 线）上，随 26.6.7 发布；26.6.8–26.6.10 都带。26.6.10:Package.swift:11 声明 iOS 18 与 Catalyst 17。
  • 27 线没有 UIKit：合进 UIKit 的提交 2fb58a810 不是 27.2.0-alpha.2、也不是 origin/xcode-27 的祖先；27 线目前停工；0014 把 27 线的 UIKit 写成非目标。
  • 26.6.10 的 xcframework 有 macos-arm64、ios-arm64、ios-arm64-simulator、ios-arm64-maccatalyst 四片，每片只有 arm64（2026-11-28 下载核对）。
  • 越狱版 target 是 ARCHS = arm64e，链接不了；visionOS 不在 0014 的平台里。
  • iOS 真机切片未签名、动态库、开了 library evolution：App 要自己嵌入并签名；主题资源在框架里，不需要另外链接系统框架。
2. UIKit 版缺什么

排除清单 UIKitExcludedFiles20261122.tsv（632 行）：折叠（FoldingController、FoldingRibbon）、行内展开（Gap 系列）、吸顶标题、缩进参考线、macOS 查找面板（iOS 用 UIFindInteraction）。iOS 版 SourceEditorView 继承 UIScrollView，自己实现 UITextInput。

3. 桥接用到的 API 在 UIKit 下的情况
  • 有：contentView、layoutManager、dataSource、isEditingEnabled、hideCursorWhenEditingDisabled、gutter（lineNumberFont 是 UIFont）、小地图与地标图标（图标协议返回 CGImage）、不可见字符、MARK 分隔线、selectedSymbolHighlightDelay、showCallout(for:)、findQuery、setTheme(_:)、contentViewContentMargins。
  • 共享、无平台条件：SourceEditorDataSource、SourceModelLanguageService.nodeTypeAdjuster / hostExtension、tokenRangeAtPosition、SourceEditorTheme(name:dictionary:fontSizeModifier:)、布局覆盖与 LayoutVisualization。
  • 换了签名：selectTextRange(_:scrollIfNeeded:)、positionAtPoint(_:absolute:)、perform(TextFindAction)；setSelection(…scrollPlacement:) 与 scrollTo(position:…) 在 iOS 上是空壳。
  • 没有：scrollView、enableCmdClickMultiCursor、contextualMenuItemProvider、addCursorRectOverrideProvider、滚动状态保存与恢复、defaultScrollViewContentInsets、缩进参考线、折叠条、吸顶标题、editorGapController、foldingController。
  • 四个逻辑文件能原样编（只换 import）；ReadingStateCache 存的东西在 iOS 上取不到，改存 contentOffset。
  • 注释标签与行尾标签画得出来，但「可折叠」靠 FoldingController，点击靠 AppKit 的 event consumer；iOS 的事件管理器只收间接指针，SEEvent 的字段不公开。
  • 26.6.10 与 27.2.0-alpha.2 之间，桥接用到的共享 API 签名没有一处不同。
4. iOS 版的接法（重建版的 UIKit 示例）
  • 主题：内置 defaultDark / defaultLight 按外观选，setTheme(_:)，外观变化时重设。
  • 行号：自建 SourceEditorGutter；每次换主题都要重设 lineNumberFont 并再调一次 enableLineNumbers()。
  • 文本：每次新建 SourceEditorDataSource；语言 .swift、.objc、.cpp。
  • 查找：findInteraction.presentFindNavigator(showingReplace: false)；第一响应者时 ⌘F、⌘G 自动可用。
  • 不可见字符要 App 自带 SF Mono 三个字重并登记在 UIAppFonts，缺一个就崩。
  • 页面出现时由控制器自己抢首响应者，免得键盘弹出；示例里没有只读用法。
5. 只读时点按（推测，未实测）

单击走 SetSelectionRange，然后 becomeFirstResponder()；双击还会走 ShowKeyboard；框架里没有压住软键盘的代码。推测只读时一点也会弹键盘。打字改不了文本：replaceTextInRange 经 isEditableInRange 拦下。

6. 头文件冲突

macOS 那个冲突的 NSScrollViewDelegate 声明在 TARGET_OS_OSX 条件里，iOS 上不出现。iOS 上伞头文件带进 UIKitSPI.h（UIKeyboardImpl 与几个 UIKit 类的私有 category）；UIFoundation 与 AppKitPlus 的检出里没有同名声明（查的不是 RV 钉的发布版）。所以 iOS 照旧只在桥接里 internal import。

7. RuntimeViewer 这边的现状
  • 桥接 target 只编 macOS（工程级 SDKROOT = macosx），公开接口全是 AppKit 类型。
  • 下载脚本只取 macOS 切片（FetchSourceEditorScript.sh:104），整体替换 Frameworks/；嵌入脚本发现标记与 pin 不一致就报错。
  • 正式发版每次都编 iOS 模拟器版（release.yml:168 → ArchiveScript.sh:481–496）。
  • iOS 工程三个 target 共用一个 synchronized folder，设置写在工程文件里，不在 Tuist 里；越狱版已有跨工程依赖的先例；SDKROOT = auto 的依赖跟随宿主平台。
  • macOS 内容区按 isAvailable 选两种显示方式，两者绑同一个 ContentTextViewModel。
  • ContentTextViewModel 在 iOS 上取数走 #else：转换选项固定为默认值，注释结构、宏展开、C 导入类型名标签都关着。附带发现：iOS 已有的 Transformer 设置页因此不作用于内容区，登记为后续项。
  • iOS 没有任何代码跟随 SelectionRoute，点中了也不会跳。
  • EditorSettingsView 与 SourceEditorFrameworks 整个是 #if os(macOS)。

替代方案

8 条，都已否决
  • 两端都退回 26.6.10：macOS 会丢掉 27 线的修复（行内展开的关闭按钮在 macOS 27 SDK 下点不了），是回归。用户定了 iOS 单钉。
  • 等 27 线合 UIKit：27 线停工，0014 也写成非目标，等不到日期。
  • 另建 iOS 专用的桥接 target：四个逻辑文件要复制或另拆 target，同名模块会各 import 一份；多平台 target 有 RuntimeViewerMobileServer 的先例。
  • iOS App 直接 import SourceEditor：UIKitSPI.h 的私有声明会不会与 UIFoundation 钉的版本冲突没验证；经桥接与 macOS 一致，退回 UITextView 只靠一个 isAvailable。
  • 用 canImport(RuntimeViewerSourceEditorBridge) 区分 iOS 版与越狱版：两者共用产物目录，越狱版会 import 到桥接、链接才失败。
  • 把 iOS 框架放进 Frameworks/ 的子目录：Fetch 整体替换 Frameworks/，两个平台会互相删。
  • 第一版就做点击跳转：iOS 没有跟随 SelectionRoute 的代码，属于愿景第四步。
  • 第一版就做注释标签（只画不折叠）：iOS 的 ContentTextViewModel 不取注释结构；CommentDecorationController 还要大改坐标、外观与滚动监听。

影响

用户可见变化

  • iOS 普通版的内容区变成 Xcode 风格的编辑器：行号、语法与语义着色、设置里的主题，可选小地图、MARK 分隔线、插入点。
  • 点一个标识符，同名的其他出现一起高亮；切到别的对象再回来，回到上次读到的位置。
  • 内容页导航栏右侧多一个放大镜按钮，打开系统查找；接了硬件键盘时 ⌘F、⌘G 可用。
  • Settings 多一页「Editor」，列上面四项。
  • 原来 UITextView 能选中文字、拷贝；SourceEditor 实现了 UITextInput，预计同样能选中与拷贝，只是不弹键盘（未实测，第 6 步在模拟器上看）。
  • 越狱版与 visionOS 不变。

可发现性

内容区直接换，不设开关，与 macOS 的 0072 一致；显示选项沿用 Settings.Editor 现有默认值（小地图默认关）。

数据与配置兼容

不新增持久化的设置，accessPersistedValues() 与 SettingsPersistenceTests 不用改；阅读位置只在内存里。

平台与最低版本

iOS 版本来就是 iOS 18.0，不变。只有 arm64：真机与 Apple 芯片 Mac 上的模拟器用 SourceEditor，模拟器通用构建的 x86_64 切片退回 UITextView。macOS 不变。

发布

不需要新的权限、entitlement 或隐私清单条目。release.yml 多下 26.6.10 的四个 zip（约 69 MB），发版附带的 iOS 模拟器版会带上四个框架、体积增加；macOS 的公证与 Sparkle 不受影响。iOS 真机版的框架由嵌入脚本签，真机版目前不在发版流程里。
